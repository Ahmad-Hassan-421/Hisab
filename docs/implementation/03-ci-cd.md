# Hisab CI and signed release procedure

Android CI (Java 17, Gradle 8.5, Android API 34) checks changed-line formatting, runs JVM tests and Android lint, verifies the QA debug APK signature, compiles the unsigned release APK, and runs a Room migration test on an Android emulator. CI uploads test and lint reports and a separate loopback-only debug APK with application ID `com.example.hisab.qa`.

Backend CI checks formatting, shell syntax, and tracked content, compiles and tests the Ktor app, runs the extended API regression against a disposable MongoDB replica set, and builds the production container without deploying it. OSV-Scanner checks the resolved Gradle runtime graph, including transitive libraries. It fails the job if the scan fails or reports remaining known vulnerabilities. Backend CI uploads the dependency report, test outputs, and logs. Render automatic deployment remains disabled in `render.yaml`; this workflow does not deploy to Render.

The release workflow accepts a stable `vMAJOR.MINOR.PATCH` tag on the default branch (either a tag push or a manual run using that tag). The Android and backend workflows run for that commit. Publication waits for both workflows, an unsigned build with the configured HTTPS origin, and a signed APK whose package ID, version name, increasing Android version code and signing certificate match the release configuration. The workflow verifies the SHA-256 checksum again before publishing the draft. No tag or production release was created for this phase.

Before a real release, configure the repository variable `HISAB_RELEASE_API_URL` and the `android-release` environment. Configure environment variables `HISAB_ANDROID_CERT_SHA256` (64 hexadecimal digits from the installed signing certificate) and `HISAB_PREVIOUS_VERSION_CODE` (the highest version code distributed so far). Restrict the environment to approved version tags and reviewers where GitHub settings support those controls. Add the existing signing material as the environment secrets `HISAB_ANDROID_KEYSTORE_BASE64`, `HISAB_ANDROID_STORE_PASSWORD`, `HISAB_ANDROID_KEY_ALIAS`, and `HISAB_ANDROID_KEY_PASSWORD`. Do not create a new production key for an existing sideloaded installation. After publication, update the previous version code in the environment. If a draft already exists after a failed attempt, inspect the draft and checksums before resolving it; the workflow does not overwrite its assets or tags.

The previous pipeline did not retain test results, verify migration on a device, or audit resolved backend dependencies. The new audit initially reported Ktor 2.3.9 ([GHSA-8qv4-773j-c979](https://github.com/advisories/GHSA-8qv4-773j-c979)) and Guava 32.1.1-jre ([GHSA-xxph-c9ww-hj94](https://github.com/advisories/GHSA-xxph-c9ww-hj94)). Ktor moved to 2.3.13 and the runtime Guava dependency to 33.7.2-jre.

Local verification: actionlint found no errors in the three workflows, the backend unit test and all 90 API checks passed with the new libraries, and OSV returned no findings for the 115 resolved backend packages. Android passed 34 JVM tests, lint, debug and unsigned release builds, and an actual Room version 1 to 4 migration on an Android API 36 emulator. The migration preserved the profile and PKR 1,234.567 ledger entry. A disposable signing key verified the local signing and checksum commands. Docker and a production signing identity were not used locally; the API 34 runner, container build, and release configuration need remote verification.
