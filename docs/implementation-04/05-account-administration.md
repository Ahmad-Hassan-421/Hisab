# Account administration

Atlas exposed the existing `hisab_db` database with `userDocument`, `hisabGroupDocument`, `hisabEntryDocument`, and `hisabRequestDocument`. A read-only aggregate found six users, including one with an admin role. All six have string user and Hisab IDs, profile fields, and numeric creation and update timestamps. Their records have no verification, phone, or reliable last-activity field. Group member and former-member arrays use the existing string IDs. The user collection already has separate `_id`, email, and Hisab ID indexes. The groups, entries and invitations have membership, group, and participant indexes.

Hisab now enforces the current account role and status on the server for every admin request. The directory reads existing and new records with an explicit list of permitted fields. It sorts newest registrations first, paginates on the server, and supports prefix searches and status filters. A legacy missing creation date stays unknown. The overview uses real counts. Suspension and reactivation are limited to ordinary users, preserve all relationships and financial records, and revoke older sessions. A MongoDB transaction records each status change in `admin_audit_log` together with the actor, target, time, and states. Directory requests use a bounded page size, query deadline, and per-admin request limit.

MongoDB roles and Hisab roles are separate. The connected Atlas project lists a database principal with `atlasAdmin`. A deployed runtime can use a separate `readWrite` role scoped to `hisab_db` for Hisab collections and indexes. Confirm the deployed credential independently before changing it. The existing production admin was discovered by aggregate count, and no real account was selected, created, promoted, suspended, or modified.

To provision an authorized account, have the owner sign in and verify their recovery email. Confirm both their registered email and shareable Hisab ID. Set `MONGO_URI` and `MONGO_DATABASE` using an authorized operator credential and install PyMongo. Run `python scripts/provision_admin.py --email <verified-email> --hisab-id <hisab-id>` for the read-only eligibility check. After review of the identified production account, repeat the check with `--apply --operator <reviewed-operator-id>` to assign the role and record the audit event in one transaction. The owner signs in again after provisioning. Existing administrators require no new assignment.

The disposable MongoDB integration suite passed ordinary-user denial, role changes rejected through signup and profile edits, reviewed provisioning, legacy records, new registration, search, pagination, field exclusion, role revocation, and preservation of existing Hisabs across status changes. On the C51, Hisab QA hid Admin for an ordinary user and let a provisioned administrator search, suspend, and reactivate that account. Backend and Android builds and unit tests passed, and Android lint reported zero errors.
